# Data Lake — Phase 1, for the owner's checkpoint

2026-10-10. Phase 1 is the whole contract a worker model builds from, written before any feature PHP: **the schema** (db/001–018, proven),
**the tool surface** (`docs/datalake-mcp-tool-surface.md`), **the action manifest** (`docs/datalake-action-manifest.md` → `mcp/action_registry.json`),
**three build specs** and **eleven slice specs** (`docs/build-specs/`). The owner approves them together (design §10); nothing of Phase 2 starts before.

## Decisions the specs took (the design left them open) — for the owner to confirm or change

The ones worth reading first are marked ★.

| # | Decision | Where | Why |
|---|---|---|---|
| ★1 | **The two shipped agents get no data access on install** — an admin grants the Expert and the Steward what they may read (a zone, a tag, datasets) | access-and-policies §6 | deny-by-default (D6) holds for agents too; until a grant, the Expert answers from the catalog and metrics' definitions only |
| ★2 | **Until K38, an agent in a person's chat turn is refused confidential and personal datasets for reads AND writes** (`k38_pending`) | access-and-policies §6, query-service §3 | fail closed (D8): the kernel does not yet say who asked |
| ★3 | **A personal-data proposal at ≥ 0.8 confidence masks the column at once** (`classified_by = rule`) and still waits for a person to confirm; below 0.8 it is only a proposal | lake-engine §3 | a likely email column is masked from its first load (D10), never left open while it waits |
| ★4 | **Only product datasets can be shared with a sibling application**; `product_rows` also serves a person through the API (≤ 1,000 rows) | api-keys-k7 | siblings read the owned, certified surface (D14) |
| ★5 | **The owner's five reads are seeded** by `bin/seed_k7_sources.php`: GL `account_balances`, `ar_aging_summary`, `ap_due_summary` (no paging), Inventory `sales_closed` and CRM `deals_won` (offset, 500 a page, a 92-day window moving forward), all nightly, into `raw.gl_*`, `raw.inventory_sales_closed`, `raw.crm_deals_won`; `no_connection` pauses a source, five failures pause and notify | sources-pulls | the owner's (c) |
| ★6 | **Exports and transforms run in the writer** with the person's (or the transform owner's) policy frozen at the moment of the request | query-service §1, lake-engine §1 | one door's rules, applied where the files are written |
| ★7 | **Archive retention is Extended**; v1 retention deletes | health-erasure | the design's `action` column kept; archive needs a second storage tier |
| ★8 | **A nightly backup timer at 02:00** (before the 02:30 maintenance; `deploy/datalake-backup.{service,timer}`) and the restore drill into `<DB_NAME>_drill` made and dropped as postgres by the provision script — the writer's role never gets CREATEDB | health-erasure, lake-engine §6 | D11's backups, owned by the application |
| 9 | The query service compiles the policy itself from the caller's identity (callers never send a policy); only uid `www-data` may connect (SO_PEERCRED); one socket per worker instance (`/run/datalake/query-N.sock`), one request at a time, `busy` at once, the client rotates for 2 s | query-service §2 | the policy is never forged by a caller; the pool's limits are real |
| 10 | Rate and concurrency admitted in PostgreSQL (`dl_query_admit`, advisory-lock slots — slice 3's migration) | query-service §2 | the limits hold across instances |
| 11 | Running SQL is a read (the `/sql/run` door, the records tool `query_run`), never a registry action | query-service-editor, manifest | the Actions MCP is for changes |
| 12 | Saving a query and freezing a transform dry-run the SQL first (`dry_run`) | query-service §7 | the datasets a SQL reads come from the parse, never from a person |
| 13 | A row filter is checked by the query service (`check_row_filter`) before a grant is saved | access-policies, query-service §7 | a filter that cannot run is refused at save, not at the reader's first query |
| 14 | Zone and tag grants are `grants.manage`'s only; dataset grants also their owner's; a dataset with no owner sends its requests to `grants.manage` | access-and-policies §2, §4 | broad grants are the admin's |
| 15 | Personal data is confirmed by people only; agents propose | access-policies | D10 |
| 16 | Below `discover` a 404 identical to "no such dataset"; `discover` without the level a 403 with Request access | access-and-policies §1 | a hidden dataset never confirms itself |
| 17 | A sandbox upload is typed by the confirmed mapping (a cell that does not cast is NULL + a `CAST` reject); a raw load stays all text | uploads-loads, lake-engine §3 | a person's own file is usable at once; raw stays replayable |
| 18 | The sniff's 50 sample rows are nulled once the mapping is confirmed, discarded or expired | uploads-loads | personal values never linger in `upload_sessions` |
| 19 | The writer runs `writer_concurrency` jobs as threads of one process, each with its own DuckDB connection and a share of the memory; `dl_job_enqueue` wakes it with `pg_notify` | lake-engine §1 | no hard polling; the memory bound stays the unit's |
| 20 | An incremental promotion starts from the last completed promote's raw snapshot; `incremental_merge` is refused by the writer for an aggregate, a window or a DISTINCT at the top | lake-engine §4, §5 | FINDINGS §6 |
| 21 | An output column that sqlglot shows comes straight from a personal input column inherits its personal kind | lake-engine §5 | masks follow data through transforms |
| 22 | The writer unlinks every landing file; PHP never deletes from `landing/` | lake-engine §6 | one process owns the files' lifecycle |
| 23 | A verify that finds anything fails the erasure (it is never "done" with a trace left) | health-erasure | the proof is the point |
| 24 | Credentials sealed under a new `DL_SECRETS_KEY` with Inventory's `credentials.php` (env, `.env.example`, ROOT_STEPS) | sources-pulls | the estate's sealed-credential pattern |
| 25 | `postgres` sources are pulled in PHP with a server-side cursor, 50,000 rows a page, plus a weekly row-count reconciliation | sources-pulls | R48 |
| 26 | The ask conversation lives in the PHP session (the last 20 turns); "Show SQL" reads the query run, not the reply | agents-steward-admin | nothing of a conversation is stored in the lake |
| 27 | The Steward's duty schedule stays the kernel's; the lake's hour fields are informational; a dispatch runs as the dataset's steward, else its owner, else the first Lake admin | agents-steward-admin | the kernel runs duties |
| 28 | `steward_propose` refuses a re-proposal dismissed within 30 days and anything over the daily cap (20) | agents-steward-admin | a short, right list |
| 29 | A `policy` refusal (a policy that could not compile) notifies the admin once a day | query-service §4 | a broken filter is an incident, not a silent refusal |
| 30 | A K7 consumer's audit rows carry `key_label = 'k7:<app>'`; `X-OS-Consumer-Agent` is recorded, never used to widen access | access-and-policies §7 | K26 |
| 31 | The dataset page's frame owns all eight tabs (About, Columns, Usage, History built in slice 1; Preview, Access, Quality, Lineage filled by slices 2, 4, 5, 7) | catalog | one page, many slices |
| 32 | The SQL editor is a plain textarea with server-fed completion of my dataset keys; the ODCS YAML is our own small writer; XLSX exports stop at Excel's row limit, marked truncated; charts are server-rendered SVG | query-service-editor, contracts-quality, transforms-products-lineage | no new client library |
